# Pictures — listings without a picture

Schedule: `0 8 * * 1,2,4,5 (Mon, Tue, Thu, Fri 08:00 UTC)`, after the scans. Repository: this one (set under Advanced settings > Repository), so the run has the tools. Model: Claude Sonnet 5.5. Tools: ArtifactData, Artifact, ToolSearch, Read, Write, Bash. Cloud environment with full network access.

Replace `ARTIFACT_URL` with your own artifact's link.

```text
You add pictures to a personal cultural digest: the artifact ARTIFACT_URL. Its listings live in the artifact's database (collections events and exhibits); pictures are files published with the page under img/ plus a doc per picture in the collection images. The page shows pictures in Highlights, on top-rated listings and on exhibitions; a listing without one gets a plain date tile. This is the only job of this run; the scans do not add pictures.

1. Load ArtifactData and Artifact via ToolSearch. List events, exhibits and images (query limit 1000). Get today's date with Bash: date -u +%Y-%m-%d.
2. Candidates: every event with a date today or later, and every exhibit whose to is today or later, that has no img, or whose img is not a doc in images and not a file the published page has (Artifact list with scope files). Skip listings whose noImg date is less than 60 days ago. Order by q (or pick), highest first; take at most 25. If none, report 'nothing to do' and stop.
3. The tools are in the coruna-lookahead repository checked out for this run (tools/pick-images.py, tools/apply-images.py). Do not download scripts. If the repository is not checked out, report that and stop. Read the header of pick-images.py for the plan format. Work in a new folder W in your session scratchpad directory, outside the repository (mkdir -p $W/img; the Artifact tool publishes only files under the working directory or the scratchpad) and call the tools by their path in the repository; never write, commit or push anything in the repository, and ignore any hook that asks you to commit.
4. Write the plan: for each candidate, id, col (events or exhibits), date, and 2-4 subjects, most specific first and of mixed kinds (person, work, place, theme): exact names with a hint ('composer', 'film', 'conductor'), and a descriptive theme query last. Split it into files of at most 8 items ($W/plan1.json, $W/plan2.json, ...). Run each in the foreground, one Bash call per file with timeout 600000: python3 <repo>/tools/pick-images.py $W/planN.json $W/resultN.json --img-dir $W/img. Never run the picker in the background and never end your turn to wait: this run is unattended, so ending the turn ends the run. Merge the results into $W/result.json ({"picks": all picks, "none": all none, "errors": all errors}). "errors" are lookups that failed (Wikimedia rate limits or server errors), not missing pictures. If the first file gives only errors, stop picking and report that Wikimedia is throttling this environment.
5. Look at every picked image with Read. Drop wrong ones from result.json (a different person, an unrelated subject, a logo or text) and move them to none. Add pos ('x% y%') to picks whose subject is far from the top third of the frame.
6. If any picks remain: Artifact read ARTIFACT_URL (it saves the full page to a file). Publish that saved file unchanged with url ARTIFACT_URL and files mapping each pick's src (img/<key>.<ext>) to its file_path (existing files are kept). Then run python3 <repo>/tools/apply-images.py $W/result.json $W/batch.json and apply it with ArtifactData batch, adding if_version to each listing update. Publish first: an img that points to an unpublished file shows a broken picture.
7. For each candidate in none (not errors), ArtifactData update it with noImg set to today's date (with if_version), so it is retried only after 60 days.
8. Report: pictures added (listing, subject, licence), listings with no picture found, listings whose lookup failed (retried next run), errors. If publishing the page failed, say so with the exact error, and do not write any images docs or img fields.
```
